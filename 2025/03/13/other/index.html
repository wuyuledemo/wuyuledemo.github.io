集合

  1. List
    1. ArrayList：底层用数组实现，初始容量为0，第一次增加数据容量为10，之后每次扩容原来的1.5倍，每次扩容都需要浅拷贝数组（**面试过**）
    2. LinkedList：双向链表实现，插入删除快，随机访问慢
  2. Set：不存在重复元素，无序
    1. HashSet：通过HashMap实现，所有的Key都是用相同value，用key保证元素的唯一性，但不保证有序性
    2. TreeSet：通过TreeMap实现，元素有序
  3. Map：允许重复
    1. HashMap：jdk1.8之前是数组加链表（拉链法），1.8之后当链表长度大于8使改用红黑树（这个put**面试过）线程不安全**
      • 首先将要添加的键通过hash计算在数组的位置
      • 若数组中那个位置无键值对则直接添加，若相同则覆盖，若不同，则比较头节点的键值对是否相同，相同则覆盖
      • 不同的话如果是用普通链表存储，则直接遍历查询，若有相同的则覆盖，如果遍历完了，还是没找到相同的，则将该键值对添加至头节点，若链表长度达到阈值（默认为8）则将链表改为红黑树
      • 若为红黑树则遍历整个红黑树，有相同的则覆盖，无相同的则添加
      • 最后计算负载因子（默认为0.75，键值对的数量与数组的长度的比值），若超过则创建一个2倍原来大小的数组，将原来数组中的元素重新经过hash运算添加到新数组中
    2. HashTable：数组+链表实现
    3. TreeMap：红黑树（其实也**面试过**，但不会）
    4. ConcurrentHashMap：Node数组+链表+红黑树实现，线程安全
      • 在JDK1.7的底层采用是分段的数组+链表 实现，每次需要对数组内的元素进行修改时就得获得那一段数组的锁（segment锁）
      • 在JDK1.8之后就采用了乐观锁（不提前加锁，只有在提交更新时才加锁检查冲突），如果所取的元素hash值不冲突则不需要加锁，如果冲突也只需锁住当前操作的链表的头节点。

SSM

Spring

  1. 理解：(@Configuration,@Autowired,@Controller,@Service,@RequestParam,@PathVaribale)
    • 控制反转： Spring容器使用了工厂模式为我们创建了所需要的对象，我们使用时不需要自己去创建，直接调用Spring为我们提供的对象即可
    • 依赖注入：将对象的依赖关系从代码中分离出来，由外部容器（如 Spring 容器）在运行时注入。
    • 面向切面编程：我们将一个个对象某些类似的方面横向抽象成一个切面，对这个切面进行一些如权限验证，事物管理，记录日志等公用操作处理的过程就是面向切面编程的思想。

Spring MVC

  1. SpringBean的生命周期

  2. Spring框架中的单例bean是线程安全的吗

    • 不是，当多个用户同时修改单例的成员属性时，就会出现线程安全问题
    • 解决办法：将bean的作用域由“singleton”变更为“prototype”。

  3. Spring如何处理线程并发问题

    • ThreadLocal（空间换时间）：为每一个线程提供一个独立的变量副本
    • 线程同步机制（时间换空间）：加锁，线程访问需要获取锁

  4. SpringAop（切面，切点，通知）

    • 前置，后置，返回，异常，环绕。

  5. 事务失效

    • 方法内部出现异常，但没有抛出
    • 方法抛出检查型异常，且没有在@Transactional注解配置rollbackFor属性
    • 事务注解为公开（不是public）

Mybatis

  1. #{}和${}的区别
    • #{} 是预编译处理
    • $ {} 是字符串替换。（可能直接换成通配符导致SQL注入）
    • Mybatis在处理#{}时，会将sql中的#{}替换为?号，调用PreparedStatement的set方法来赋值；Mybatis在处理时，就是把 {}时，就是把时，就是把{}替换成变量的值。使用#{}可以有效的防止SQL注入，提高系统安全性。

java基础

  1. 泛型在循环中自动装箱会创建多余的对象，影响性能。

  2. Integer必须通过实例化给对象赋值，不然会出现空指针异常

  3. 通过Integer.valueOf(int)创建对象时，并不会每次都生成新的实例，而是复用缓存中现有对象。他自己内部实现了应该静态缓存池

  4. 接口成员变量默认为public static final，必须赋值，不能修改，其所有的成员方法都是public，abstract的。只能包含常量。

  5. 抽象类成员变量默认为default，抽象方法被abstract修饰，不能被private，static，synchronized和native修饰，以分号结尾。

  6. 抽象类不能加final

  7. 接口内的私有方法只能在接口内部使用，不能被实现类访问

  8. 抽象类不能被直接实例化，但通过继承抽象类并实现其所有的抽象方法的子类是可以被实例化的

  9. 在 Java 中，静态内部类（Static Nested Class）和非静态内部类（Inner Class）的对比

    特性 静态内部类（Static Nested Class） 非静态内部类（Inner Class）
    关键字修饰 用 static 修饰 无 static 修饰
    依赖关系 不依赖外部类实例 必须依赖外部类实例
    内存泄漏风险 无（不隐式持有外部类引用） 有（隐式持有外部类引用，需谨慎使用）
    访问外部类成员权限 只能访问外部类的静态成员 可访问外部类的所有成员（包括私有成员）
    实例化方式 无需外部类实例，直接通过外部类名实例化 必须通过外部类实例创建

  10. 深拷贝和浅拷贝

  • 深拷贝：将对象所有的引用类复制一份，而不是共享引用
    • 实现方法：
      • 序列化和反序列化
      • 手动递归复制
      • 实现Cloneable接口并重写clone方法
  • 浅拷贝：字段值复制，引用共享

  1. java创建对象除了new还有什么

    1. 反射创建对象
    2. 反序列化创建对象
    3. 通过clone创建对象

  2. new出的对象什么时候回收，根据垃圾回收算法确定，比如引用计数器法，某个对象的引用计数器为0时，表示该对象不再被引用，可以回收。

  3. 什么是反射？

    • 允许程序在运行时动态获取类的信息并操作类或对象的机制

    • 有什么用

      • 比如AOP通过反射实现方法拦截

      • 或者加载数据库驱动

  4. java异常

    • Error（错误）
    • Exception（异常）
      • 非运行时异常（ClassNotFoundException）
      • 运行时异常（NullPointerException空指针异常）
    • 抛出异常为什么不用throws
      • 如果异常是未检查异常或者已经被处理，则不需要使用
      • 未检查异常是继承RuntimeException类或者Error类的异常

  5. == 与equals的区别

    • 对于字符串“==”比较的是对象在内存中的首地址，equals比较的是内容是否相同
    • 非字符串两者相同，比较的是内存中的首地址
